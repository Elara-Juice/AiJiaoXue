# 督导四入口界面改造与调试说明

更新日期：2026-10-28。本次改造在 `feature/yzj-ui-ai-demo` 分支完成开发与验证，后按项目负责人要求发布到 `main`；具体版本以 Git 提交记录为准。

## 本次界面

延续浅色背景、白色内容区和橙色重点操作。督导登录后的底部导航调整为四个入口：

| 入口 | 可以完成的操作 |
| --- | --- |
| 工作台 | 继续当前课堂、新建督导、查看今日听课、待评价与改进事项、最近发布的报告 |
| 督导任务 | 按课程、教师、任务编号搜索；按状态筛选；进入课堂档案；根据实际进度继续采集、分析、核验或评价 |
| 改进跟踪 | 按正式问题查看教师响应、已确认计划、措施进度、实施记录与附件、复评及核验历史 |
| 我的 | 查看身份、设置分析代理地址与设备令牌、检查服务连接、查看使用帮助、退出登录 |

任务内部提供“概况、采集、分析核验、报告、关联改进”导航。进入深层页面后底部四入口收起，保留任务步骤与返回操作。录音尚未停止保存时，不能直接通过步骤标签离开采集。

课堂档案显示课程与教师、任务日期和节次、授课章节、本节课已选教学目标与知识点、本人同课程历史报告。复评任务额外显示原问题。

## 闭环走通方式

1. 用督导账号登录，从“督导任务”新建课堂，检查课程范围。
2. 开始采集，录音或导入音频，保存图片、互动及参与记录。
3. 结束采集后进入分析页，检查材料、启动分析、查看处理进度及结果；打开证据进行人工审核。
4. 填写人工评价并发布，进入正式报告，选择“查看教师改进与复评”。
5. 切换到该课程的教师账号，查看反馈、确认改进计划，在改进待办中提交措施状态、实际执行记录和材料。
6. 切回原督导，在“改进跟踪”选择具体问题，查看教师行动，创建复评任务。课程、教师、原问题自动关联，只需填写新的日期、节次和章节。
7. 完成后续课堂采集、分析与正式评价，通过“关联改进”返回原问题，进入证据对照与人工核验。

“待教师响应、实施中、待复评、已关闭”均由实际记录计算。教师草稿不会显示给督导；措施完成不会直接关闭问题；部分改善仍待复评。只有证据通过校验、人工确认“本次已解决”且“本次未再观察到”原问题时，才显示已关闭。无效或旧版核验不会用于关闭问题。

创建复评与建立问题关联使用同一事务。早于原课堂、同日节次重叠、重复任务或权限不足时，不留下孤立任务。

## 在 Android Studio 中调试

打开现有项目 `D:\大三上\软件项目管理\实验\4\AiJiaoXue-yzj-sprint3`，或当前映射的 `T:\` 项目。选择 `app` 运行配置和 `AiJiaoXue_API37` 模拟器，点击 Run。

本次测试已把最新 Debug APK 覆盖安装到现有模拟器，保留原应用数据。督导演示账号可使用 `sup01`，初始密码 `123456`；如果曾修改密码，以修改后的密码为准。

重点体验：四入口切换、搜索和筛选、任务步骤跳转、录音期间离开提示、正式报告进入改进、问题详情创建复评、复评后回到原问题核验。可分别用空数据、处理中、有正式报告和有教师执行记录的状态观察页面。

项目目前仍通过同一设备上的本地 Room 数据在角色之间协作，演示教师响应需在同一模拟器切换账号。本次没有新增跨设备同步或消息推送服务。

实际云端分析继续使用原有代理、DeepSeek 与百炼配置。“我的 → 分析服务设置”可以保存地址与设备令牌并检查连接；连接检查不会调用付费推理，也不代表完整转写、图片分析已经跑通。本轮验证没有调用云端推理。
