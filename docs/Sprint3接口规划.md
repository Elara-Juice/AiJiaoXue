# Sprint 3 接口延续说明

本文件记录 2026-10-24 的 S2 个人实现为后续迭代保留的关联点，不表示 S3 已经实现。

现有链为 `taskId → evaluationId → ImprovementPlan → ImprovementItem → ImprovementMeasure`。措施可以关联 `suggestionId`，建议记录发布快照标识及审核版本键；发布快照保留原分析／修正标识、实际审核人、正文和依据摘要。原分析删除后，保留的快照继续解释当时的措施来源。

| S3 能力 | 可复用的当前关联 | 后续需要增加的内容 |
|---|---|---|
| 改进落实记录 | measureId、planId、teacherId、基础待办状态 | 实际措施、实施时间、材料及权限，区分计划文本与真实执行记录 |
| 后续课堂复评 | 原 taskId、问题／事项与措施标识 | 后续 taskId、复评方法、口径和可比较指标，避免仅凭措施勾选完成推断教学改善 |
| 重点问题改善核验 | 原问题快照、发布依据和审核版本 | 复评判断、前后证据、审核人员及时间；不能把已冻结发布快照原地改为新结论 |
| 教师改进趋势 | 课程归属、任务日期、计划和措施 | 多轮关联、缺测处理、可比性及授权后的统计视图 |
| 整体质量治理 | 管理角色、任务和课程关系 | 汇总口径与去重、权限、说明与人工确认，不越权暴露教师个人材料 |

后续新增表优先通过稳定业务 ID 关联，生成新的版本记录。S2 的 `MeasureStatus.DONE` 只表示基础待办状态，不等于已经通过成效验证；`SuggestionOrigin.RULE_BASED` 也不应被改写成历史上的真实模型来源。若允许修改已确认计划，需引入明确的新计划版本与修改记录，保留原教师确认事实。
