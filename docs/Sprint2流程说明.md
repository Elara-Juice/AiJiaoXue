# Sprint 2 流程说明

本文按当前代码说明可运行的业务链路，不代表尚未实现的计划功能。

## 入口与权限

督导登录后进入“我的督导任务”。已完成任务卡片提供“查看记录”和“AI分析”两个操作；“AI分析”使用 `Routes.analysis(taskId)` 打开分析页。分析路由当前仅允许督导角色访问，并通过 `taskId` 定位任务。

## 业务链路

1. **督导任务**：任务在“我的督导任务”中按当前督导用户查询。演示数据包含两条已完成任务，可分别由对应督导账号查看。
2. **AI分析**：分析页点击“开始AI分析”后，ViewModel 根据 `taskId` 查询课堂材料和互动事件，再调用当前的 `MockAIAnalyzer`。该模拟分析器不依赖输入数据是否为空，固定返回 BOPPPS、互动、参与度三类结果；这不等于真实 AI 服务分析。
3. **结果保存与展示**：分析结果由 `AIAnalysisRepository` 写入 `ai_analysis_results`，页面展示结果类型、文本和可信度。再次点击会再次执行分析并新增结果，不是读取历史分析列表。
4. **证据追溯**：每条新结果都会生成一条 `AiEvidence`，关联分析结果和任务，并保存结果对应的时间区间及说明。当前生成逻辑没有填充 `materialId` 或 `eventId`，所以页面展示的是分析结果关联的时间区间/说明，不是可跳转到录音、图片或互动事件的源材料定位。分析页当前加载并展示最新分析结果对应的证据。
5. **人工审核**：每条分析结果的“审核AI结果”操作按结果 ID 打开 `Routes.aiReview(analysisId)`。审核页展示 AI 原始结论，允许编辑修正文本；保存时将原文、修正文本、是否接受以及创建时间写入 `ai_corrections`。是否接受由修正文本是否与原文相同决定。
6. **审核记录**：审核页按 `analysisId` 查询并展示该结果的历史审核记录。记录保存不修改 AI 原始结果本身。

## 当前演示数据边界

DemoData 已有属于督导账号的已完成任务，足以进入分析页。即使这些预置任务没有预置课堂材料或互动事件，当前模拟分析器仍会产生三条结果，并由分析流程生成证据记录，因此不需要额外种子数据即可演示“任务 → AI结果 → 证据 → 人工审核”。演示数据不会预先包含 AI 结果、证据或审核记录；这些数据在实际操作链路中生成并保存。
